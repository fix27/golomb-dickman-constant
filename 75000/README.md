# Постоянная Голомба–Дикмана: 75 000 знаков с интервальным сертификатом

$$\lambda=\int_0^\infty e^{-u-E_1(u)}\,du
=0.624329988543550870992936383100837244\ldots$$

Сертификат [`golomb_dickman_75000_certified.txt`](golomb_dickman_75000_certified.txt)
содержит целые $\Lambda_-<\Lambda_+$ и масштаб $S=249341$ такие, что

$$\left\lfloor 10^{75000}\Lambda_-/2^S\right\rfloor
=\left\lfloor 10^{75000}\Lambda_+/2^S\right\rfloor .$$

Значит, первые **75 000** десятичных знаков (усечение, не округление)
выведены из интервала точной целочисленной арифметикой. Ширина интервала —
$5.8205594787\times10^{-75043}$, то есть сверх 75 000 знаков остаётся
$42.2350$ гарантированных знака.

Это **новый результат**; сертификаты на 50 000 и 40 000 знаков сохранены
без изменений как предыдущие (`../50000/`, `../40000/` и `../40000-v2/`).

Digits» проверены на 75 000 знаков: PASS для A229195 (все 1 000 членов),
последовательности Earls (28, 256, 1967, 387), digit scanning, частот,
A174975 и простых усечений длин 6, 27, 57, 60, 1659, 2508. Панцифровые

Полный список — в [`SHA256SUMS.txt`](SHA256SUMS.txt). Все текстовые файлы —
LF без BOM; политика закреплена в [`../.gitattributes`](../.gitattributes).
Хеш сам по себе ничего не доказывает: он связывает имя файла с байтами и
должен сверяться с доверенным эталоном. `verify_certificate.py` печатает
`MATCH (manifest)` только при наличии манифеста, иначе честно выводит
`computed, UNVERIFIED (no trusted reference)`.

## Как проверить

```bash
cd ..   # корень репозитория

python verification/verify_certificate.py \
    --cert 75000/golomb_dickman_75000_certified.txt \
    --digits-file golomb_dickman_75000_digits.txt \
    --sha256-manifest 75000/SHA256SUMS.txt \
    --compare 50000/golomb_dickman_50000_digits.txt

python verification/audit_chunks.py \
    --ckpt 75000/gd_rigorous_ckpt_75000 \
    --cert 75000/golomb_dickman_75000_certified.txt
```

Оба скрипта используют только стандартную библиотеку Python и точную
целочисленную арифметику; при расхождении завершаются ненулевым кодом.
Для полного Arb-аудита (часы работы) нужен `python-flint` и отдельный запуск
`verification/verify_all_arb.py`.

## Оговорки

- **Полный Arb-аудит не выполнялся.** Пересчитаны и проверены только первые
  20 чанков (2 000 узлов из 476 648); все они contained. По измеренной
  скорости полный прогон занимает около 9 ч на 4 потоках (≈3 ч на 11),
  поэтому в рамках лимита на процесс не запускался. До его завершения
  сертификат опирается на исходный прогон продюсера.
- `verification/audit_chunks.py` и `verification/verify_all_arb.py` пока
  ищут только `meta_v12.json`, а здесь лежит `meta_v13.json`. Для Arb-выборки
  применялось временное зеркало вне репозитория с преобразованным
  `meta_v12.json`; сами чекпоинты и план не менялись.
- b-file для 75 000 знаков **не создавался**; в `50000/` и `40000/`
  сохранены b-file предыдущих результатов. Проверка 102-значного префикса
  OEIS A084945 входит в `verify_certificate.py`: первые 102 знака совпадают
  с опубликованным префиксом A084945.
- Независимая квадратура на 300 знаков дала 320 совпадающих знаков;
  запрос на 1 000 знаков превысил лимит времени и был остановлен. Это
  численная проверка, а не доказательство.
- Простые усечения после длины 2508 проверены выборочно (2526, 9867, 17257 —
  составные), не исчерпывающе.
- Это расширение результата, а не заявка на мировой рекорд; о нормальности
  $\lambda$ ничего не утверждается.
